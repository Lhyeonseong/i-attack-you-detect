# RUNBOOK 2026-10-18 — V2 적용 → dry-run → S3 baseline 백필 (실행: 이현성)

- 대상: 운영 `postgres` 컨테이너, DB = `docker/.env` 의 `POSTGRES_DB`, 스키마 `validation`
- 접속 계정: **`validation_rw`** — validation 스키마 소유 role, superuser 아님(`rolsuper=f`). 관리자(`POSTGRES_USER`) 사용 금지
  - 컨테이너 안에서는 unix socket(`local all all trust`)으로 비밀번호 없이 접속, 호스트에서는 `127.0.0.1:5433`(`POSTGRES_PORT`) + `VALIDATION_DB_PASSWORD`
- 위치: **저장소 루트**(`docker/.env` 가 있는 develop-v2 체크아웃, 커밋 `033c479` 이상)에서 실행
- 비밀값: 명령에는 `$(grep … docker/.env)` 만 들어가므로 셸 히스토리·화면에 값이 남지 않는다. 값을 `echo` 하지 말 것
- 순서를 지킬 것. 어느 단계든 "멈출 것"이 나오면 다음 단계로 가지 말고 출력 그대로 공유
- 리허설: 운영 validation 스키마 덤프를 일회용 PG 에 복원해 (2)~(5) 동일 스크립트로 통과 확인(2026-10-18). 아래 예시는 그 출력

## (1) V2 적용 — migrate 전용 진입점 (측정·Caldera 호출 없음)

```bash
RUN_VALIDATION_MIGRATE=1 \
POSTGRES_DB="$(grep -m1 '^POSTGRES_DB=' docker/.env | cut -d= -f2-)" \
VALIDATION_DB_PASSWORD="$(grep -m1 '^VALIDATION_DB_PASSWORD=' docker/.env | cut -d= -f2-)" \
./gradlew cleanTest test --tests 'com.capstone.vuln.correlation.ValidationMigrateIT' -i 2>&1 \
  | grep -E 'MIGRATE>>|ValidationMigrateIT|FAILED|BUILD'
```

정상 출력 예시:
```
ValidationMigrateIT > migrate() STANDARD_OUT
    MIGRATE>> before=[1] after=[1, 2]
    MIGRATE>>   rank=1 v=1 validation schema by=validation_rw on=2026-10-16 23:31:49.334494 success=true
    MIGRATE>>   rank=2 v=2 measurement run by=validation_rw on=<지금> success=true
BUILD SUCCESSFUL in ...
```

멈출 것: `MIGRATE>>` 줄 없이 `migrate() SKIPPED`(env 미주입), `FAILED`, `Validate failed`/`checksum mismatch`, 또는 `after` 에 `2` 가 없음.
(`before=[1, 2] after=[1, 2]` 는 이미 적용된 것 — (2) 로 진행)

## (5) 사후 확인 (읽기 전용)

```bash
docker exec -i postgres sh -c 'psql -U validation_rw -d "$POSTGRES_DB" -v ON_ERROR_STOP=1' <<'SQL'
BEGIN READ ONLY;
SELECT label, kind, status, started_at, ended_at, git_commit, git_dirty, expected_attempts, expected_controls,
       rules_digest->>'status' AS digest_status, rules_digest->'observed_after'->>'verdict' AS observed_after
  FROM validation.measurement_run;
SELECT count(*) FILTER (WHERE run_id = 'bd2de561-a7dc-429f-8d39-fc2d70950727')                              AS attributed,
       count(*) FILTER (WHERE run_id = 'bd2de561-a7dc-429f-8d39-fc2d70950727' AND attempt_role = 'ATTACK')  AS attack,
       count(*) FILTER (WHERE run_id = 'bd2de561-a7dc-429f-8d39-fc2d70950727' AND attempt_role = 'CONTROL') AS control,
       count(*) FILTER (WHERE run_id IS NULL)                                                               AS run_id_null
  FROM validation.verdict_result;
SELECT r.label,
       CASE WHEN r.expected_attempts = count(*) FILTER (WHERE v.attempt_role = 'ATTACK')
             AND r.expected_controls = count(*) FILTER (WHERE v.attempt_role = 'CONTROL') THEN 'VALID' ELSE 'INVALID' END AS r10
  FROM validation.measurement_run r JOIN validation.verdict_result v ON v.run_id = r.run_id
 GROUP BY r.run_id;
ROLLBACK;
SQL
```

정상 출력 예시:
```
      label      |  kind  | status |          started_at           |           ended_at            | git_commit | git_dirty | expected_attempts | expected_controls | digest_status | observed_after
-----------------+--------+--------+-------------------------------+-------------------------------+------------+-----------+-------------------+-------------------+---------------+----------------
 S3-GATE-dc66322 | ATTACK | CLOSED | 2026-10-16 17:04:01.091971+00 | 2026-10-16 18:07:23.246309+00 | 17a0b04    |           |               140 |                20 | unverified    | inconsistent
(1 row)

 attributed | attack | control | run_id_null
------------+--------+---------+-------------
        160 |    140 |      20 |           0

      label      |  r10
-----------------+-------
 S3-GATE-dc66322 | VALID
```

멈출 것: run 이 1행이 아니거나 `status ≠ CLOSED`, 160/140/20/0 이 아님, `r10 = INVALID` → 출력 공유 (임의 수정·재실행 금지 — 백필 스크립트는 사전 검사로 재실행을 거부한다).
